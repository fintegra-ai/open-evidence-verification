# BOUNDARY.md — Open / Closed Module Boundary

Status: normative for this repository. Part of Faz A (NLnet pre-application
plan v2, gate A). The companion copy lives in the sibling open repository
(open-evidence-provenance); the two MUST stay consistent on the shared rules
in §3.

## 1. What is open, what is closed

| Component | Side | Home |

| `oev` CLI (`oev verify`, `oev inspect-receipt`, `oev receipt`, `oev pack`, `oev reverify`) | **OPEN** | this repository |
| Schemas (`src/oev/schemas/*.json`) | **OPEN** | this repository |

| `oept` Python package (bundle format, offline verifier, canonical JSON) | **OPEN** | sibling repository `open-evidence-provenance` |
| EvidenceOS product code (services, parsers, UI, payment flows) | **CLOSED** | `mehmet-tur/EvidenceOS-Finance` and its local working copies (EU_Demo, Muse_C29/C32/C33, Integration, QUAL_*, etc.) |
| `evidenceos_core`, `evidenceos`, `amanah`, `muhasebe`, `payment_verification`, `eu_cii_invoice_parser` (any closed import target) | **CLOSED** | closed repositories only |
| Any `case_*`, `tmp/`, `output/`, customer, or finance data artifact | **CLOSED** | never enters an open repository |

## 2. Dependency direction (one-way, enforced)

1. **Open core never imports closed code.** No module in `src/`, `tests/`,
   `conformance/`, `examples/`, or repository-root scripts may import any
   closed module name listed in §1. Enforced by
   `tests/test_import_boundary.py` (runs in every CI job that runs pytest).
2. **Closed product consumes the open core only as a pinned PyPI
   distribution** (`open-evidence-verification==x.y.z`, `oept==x.y.z`).
   Vendored copies of open-core modules inside closed repositories are
   forbidden; the closed repository's CI is responsible for that check
   (tracked in the closed-side boundary work, not here).
3. No open module may reach into the closed ecosystem transitively (e.g. by
   importing a wrapper that itself imports closed code). The denylist test
   plus the closed-side vendoring ban together close the loop.

## 3. Shared rules with the sibling open repository

1. Secret scanning: gitleaks (default rules) over the **entire git history**
   must be clean. OEVP baseline 2026-11-01 (gitleaks 8.30.1): zero findings,
   no allowlist entries. CI runs gitleaks on every push/PR; a new finding is
   a boundary violation, not a warning.
2. No `.env`, tokens, private keys, customer data, or finance records in any
   commit, ever. The only key-like artifact allowed in the open ecosystem is
   OEPT's documented test-only conformance keypair ("PUBLICLY COMPROMISED BY
   DEFINITION"), allowlisted in the sibling repository's `.gitleaks.toml`.
3. Reproducible open-side artifacts only: `case_*` / `tmp/` / `output/`
   directories are closed-side; anything needed publicly is regenerated by a
   script into neutral, byte-stable conformance fixtures.

## 4. Distribution names (decided 2026-11-01)

- PyPI: `open-evidence-verification` (this repo) and `oept` (sibling).
  Import names (`oev`, `oept`) and CLI names (`oev`, `oept`) are unchanged.
- The name `oev` on PyPI is held by an unrelated project and is NOT ours;
  never publish under it and never present it as ours.
